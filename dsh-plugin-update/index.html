DeepSeek Harness 插件

在插件页上
检查并更新插件

打开任意一个从 npm 装的插件详情页，右上角会多一个「检查更新」。有新版本就卸载旧版、装上新版； 装失败会把旧版装回去。

安装方式 GitHub
  • 不需要配置
  • 不新增侧栏入口

01 — 功能

用起来是什么样

不占侧栏，不加菜单，所有控件都在插件自己的详情页里。

01

详情页多一个按钮

打开插件的详情页，右上角「检查更新」就挨着开关和卸载。点了才去查，不点不发请求。

02

有新版本直接显示

标题旁出现「有新版本 4.10.0」，按钮变成「更新到 4.10.0」。点之前会再确认一次，确认后自动卸载旧版、装新版、重新加载。

03

失败会装回旧版

装新版失败时，把原来的依赖说明装回去，插件不会变成缺失状态。原来写 ^4.8.1 的继续写 ^4.10.0，锁死版本的继续锁死。

页面上会写清楚：已安装哪个版本、上游最新是哪个、查的是哪个 registry。查不到或不能装时也会写出原因，而不是只给一个按不动的按钮。

02 — 状态

检查结果有五种

每一种都会在页面上说明原因，不用猜。

可更新
有新版本，且 engines.dsh（没有则看 @deepseek-ai/dsh 的 peer 范围）允许当前 DSH 版本。按钮变成「更新到 x.y.z」。
不兼容
有新版本，但它要求更高的 DSH。显示要求来自哪个字段，不出现更新按钮，避免装完启动不了。
已是最新
装的就是最新版。没有可点的按钮。
读取失败
仓库读不到：离线、404 或返回的文档格式不对。会写出原因，「检查更新」可以重试。
不支持
依赖是本地链接、Git 地址、压缩包或别名。这类会直接说明不去问 npm，也不显示按钮。

03 — 怎么更新

更新时发生了什么

Host 端调用 profile 自己的 pluginManager，和插件页、plugin_manager 工具是同一套逻辑。

01

卸载

removeBundle(name)：取消选择该 bundle、卸载它的行、执行 pnpm remove。

02

安装

installBundle(spec, { enabled, registry })：装新版并重新选择。enabled 保留你原本关着的状态，不会顺手打开。

03

失败回滚

第 2 步失败就把原来的依赖说明装回去。开了 HMR 的插件替换后立即生效；从 DSH 启动起就在跑的会提示需要重启。

更新之后

  • 装配顺序会变。重装后的 bundle 排到 dsh.profile.bundles 末尾，而这个顺序就是配置优先级。两个插件改同一行配置时，更新过的那个最后生效。
  • 可能需要重启。页面会提示 restart-required 的情况，重启一次 DSH 就好。
  • 查的是同一个 registry。按插件管理器的顺序问同一批源。profile 配了 registry.npmmirror.com 就查镜像，不会绕回 npmjs。

04 — 安装

安装

插件没有依赖，也不会改你的模型、密钥或其它配置。三种装法按使用场景选。

01

从 GitHub 装

不需要先下载文件，记成 Git 地址，以后重新装一次就是升级。推荐。

dsh plugin --profile desktop install \ https://github.com/YiZhiQvQ/dsh-plugin-update
02

从本地目录装

适合要改代码的时候。记成 link: 依赖，改完立即生效，不用重装。

dsh plugin --profile desktop install \ <绝对路径>\dsh-plugin-update
03

从压缩包装

记成 file: 依赖，绑定这个文件的路径。所以 .tgz 要留在原地，移走或删掉就得重装。

dsh plugin --profile desktop install \ "D:\dsh-plugins\dsh-plugin-update-0.1.0.tgz"

也可以在插件页面右上角「+ 添加插件」里填 GitHub 地址或文件完整路径，效果一样。

05 — 问题

常见问题

几件会被问到的事。

检查的时候会往外发什么？
只读 npm 的公开版本信息，不发送本地路径、配置或密钥。只有你点「更新」并确认之后才会真的改文件。
一次检查要问多少个包？
只问当前打开的这一页。其它包的 registry 文档走十分钟缓存，不会每次都请求。
侧栏里怎么找不到它？
它不新增侧栏入口，控件只加在插件页面的详情视图里，和插件自己的开关、卸载放在一起。
更新失败会怎样？
会自动把原来的依赖说明装回去，插件仍然可用。失败原因写在页面下方，可以再点一次重试。
为什么按钮是灰的或不存在？
说明这个包不是从 npm 装的，或者当前 profile 没有在跑它。页面会写出具体原因。
